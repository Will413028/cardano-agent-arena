# 非功能需求與待驗證的產品風險

## 非功能需求

D4、D5、D7、D8 已拍板；下列門檻用於正式產品驗收。

| 類別 | 門檻 | 依據／擋在哪 |
|---|---|---|
| 每步延遲 | 連續 20 步，每筆送出至首次入塊 ≤120 秒；另記索引延遲，不當作最終性或網路保證 | 外部介面「Cardano L1 時間」；步驟 2 實測 |
| 每局成本上限 | preprod 最長正常 25 步，建局、行動、結算總 fee ≤10 tADA；可退還最低 ADA 另列 | S9；步驟 2、3 的數字 |
| 安全：合約 | validator 拒絕所有非法行動與錯誤結算；對抗測試清單見步驟 11（double satisfaction、datum 偽造、逾時濫用、UTxO 搶占）。業界基準：Cardano 常見 validator 漏洞類型，步驟 11 開工時查證並附來源 | 不變量 I1、I2 |
| 安全：金鑰 | 玩家私鑰不離開玩家端；自管 client 與官方開源本機 runner（D7） | 不變量 I6 |
| 隱私 | 錢包地址與所有行動公開且永久；登記頁明示。是否收集任何個資（例如 GitHub 帳號）依 D9 | S6、D9 |
| 可觀測性 | 索引器落後區塊數、交易失敗率、每局手續費可在 `make check` 之外的指令查到 | 步驟 11 |
| 資料保存 | 逐步正式戰局資料在 preprod 鏈上；獨立 verifier 可讀完整歷史，測試網重置不保證永久保存 | 不變量 I3 |
| 可用性 | 營運者的網站或索引器停擺時，玩家仍能用公開客戶端參賽、任何人仍能用 verifier 重播 | S5；不變量 I3 |
| 語言 | 英文或中英雙語 | S13 |

## 待驗證的產品風險

| 風險 | 目前證據 | 最便宜的驗證（需要 Will 授權才能聯絡人或公開） |
|---|---|---|
| 開發者願不願意接入 | 無（S11）；先例只證明同類競賽存在 | 訪談 5–10 位寫 Agent 的開發者；或在社群貼假門頁看報名意願 |
| 會不會反覆參賽 | 無 | 手動主辦一場鏈下比賽（現成框架、不寫合約），看有幾人回來打第二場 |
| 哪種遊戲值得反覆玩 | 無 | 同上，比較兩款規則 |
| 獨立驗證是否影響選擇 | 無（S10 明列待驗證） | 訪談時問；或假門頁 A/B 一句「戰局可獨立驗證」 |
| 賽季營運與防刷分成本 | 無 | 先記錄手動比賽的營運時數 |
| 付費 | 不適用（S13 排除收款） | — |
